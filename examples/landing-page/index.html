How a site lives on the network

No hosting account, no server to babysit, no single point of failure.

Publish a folder

c0mpute hosting publish ./public signs your site with your own key and splits it into content-addressed chunks. Only you can publish new versions.

Three copies, self-healing

Hosting nodes keep at least three copies. If a machine goes away, another picks up a copy within minutes. Every chunk is checked against its hash.

Any gateway serves it

Every gateway on the network serves every site, fetching from the fastest copy. Point a Moshpit name or your own domain at it and you are live.

Old hosting vs. the network

A server in a data center

  • One box, one region, one bill
  • Goes down when that box goes down
  • Your provider can switch you off
  • You patch it, scale it, renew it

A site on c0mpute

  • At least three copies on independent machines
  • Heals itself when a host leaves
  • Signed by your key, served by anyone
  • Free by default, pennies for preferred hosts

Put a site on the network in a minute

This exact page was published with these commands.

# install the c0mpute node and CLI
$ curl -fsSL https://c0mpute.com/install.sh | sh

# publish a folder: prints your site id, keeps 3 network copies
$ c0mpute hosting publish ./public --name my-site

# optional: pay preferred hosts from the d1sks market
$ c0mpute hosting publish ./public --name my-site --disks auto

# open it on any gateway
$ open https://gateway.c0mpute.com/s/<site_id>/

# give it a Moshpit name, no server of yours
$ moshcode name c0mpute my-site.indie <site_id>

Your spare disk can host the web

Every c0mpute node can keep copies of sites and list its space on d1sks. Install the node, leave it running, and your idle disk and CPU become part of the network.

Set your own price per GiB-month. Host payouts settle through CoinPay once settlement is switched on for the network; until then the receipts are recorded as a dry run.
